# C010 — Explain each eight-seat position before questions

This expands C007: plain groups Early/Middle/Late/Blinds are also unknown and do not solve beginner understanding. User requests a complete lesson overhaul, each seat/action flow explained before questions, and meaningful main-screen information.

Source uses eight-max codes UTG, UTG+1, LJ, HJ, CO, BTN, SB, BB. Preflop follows that order; postflop static order starts SB,BB then early-to-late ending BTN (Position.swift:12–31). Real action skips folded seats; the enum counts seat slots, not active players. PositionDrill can ask players-behind counts before teaching the complete order; beginner grouping hides codes/order until answer (ConceptDrillView.swift:1084–1237). Worked examples dump a code sequence in 3–4 steps rather than explaining each seat.

Proposed visual progression: orient eight seats around dealer-button marker; explain blind roles/contributions; highlight first preflop seat after BB; walk each seat clockwise; finish with SB/BB decision turns; introduce shared-card stage and active-seat postflop order; compare both orders on the same persistent map; only then introduce group terminology and gentle checks. Plain role descriptions first, Latin codes secondary and introduced in context. No glossary wall or decorative empty-space fill. Main area holds the map/explanation; footer holds Previous/Next or choices.

This is a pedagogical proposal, not an approved change to completion format. Preserve existing persisted three-question lessons and completion-first philosophy unless a separate data-compatible change is specified; no requirement to answer perfectly to proceed. Additional gentle checks can be ungraded teaching steps. Validate before/after-flop, active/folded seats, each beat, Back/resume, help exit, English/Korean, normal/AX5, both themes, VoiceOver and Reduce Motion. Proposed 7–8 teaching beats need novice timing/understanding tests so the lesson does not become unnecessarily long.
